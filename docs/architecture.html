1 · Arquitectura actual

Un solo origen: nginx reparte / al web y /api/* al monolito Go. Todo vive en una VM de Azure con Docker Compose.

punto de entrada código propio servicio externo línea punteada = sin uso / legado

2 · Quién corre dónde (lo más importante)

Los frontends no son servidores: son clientes que se ejecutan en el dispositivo del usuario. Solo el web necesita hosting, y únicamente para entregar sus archivos.

ClienteCómo llega al usuarioDónde se ejecuta¿Contenedor / servidor?
iOSSe publica en App Store; el usuario la instalaEn el iPhoneNo
AndroidSe publica en Google Play; el usuario la instalaEn el teléfonoNo
WebEl navegador descarga HTML/JS/CSS desde mano.appEn el navegadorSolo hosting de archivos

Una vez instalada/cargada, cada una hace lo mismo: peticiones HTTPS a api.mano.app/v1 cuando hay conexión. De ahí en adelante todo es común: gateway → backend → BD → pagos → respuesta.

4 · Cómo el sistema sabe de dónde viene la petición

Cada cliente se identifica con headers en todas sus peticiones. El gateway los lee; el backend actual los ignora sin problema.

HeaderLo envíaEjemploPara qué sirve
X-Mano-Clientweb · iOS · AndroidiosMétricas y límites por plataforma; CORS solo aplica a web
X-Mano-Client-Versionlos 31.4.2Gateway responde 426 Upgrade Required si está por debajo del mínimo
X-Mano-Buildmóviles214Diagnóstico por build
X-Mano-Device-Idlos 3 (UUID de la instalación)8f3c…Rate limit por dispositivo, anti-abuso en endpoints guest
X-Request-Idcliente o gatewayb21a…Trazabilidad cliente → gateway → core
Authorizationtras loginBearer eyJ…Lo único que el backend ya entiende hoy
Originsolo el navegador (automático)https://mano.appValidación CORS en el gateway
Ojo

Estos headers los puede falsificar cualquiera. Sirven para enrutar, medir y gestionar versiones, nunca para autorizar. La autorización sigue siendo el JWT y el rol que valida el backend. Para probar que la petición viene de una app legítima existen Apple App Attest y Google Play Integrity (opcional, más adelante).

Backend congelado

Hoy "entiende" el origen el gateway, no el backend. Caso donde el backend sí tendría que saberlo: el redirect_url del pago Wompi (lo fija a /orders e ignora el del cliente). Por defecto se resuelve con Universal Links / App Links sobre mano.app, sin tocar el backend.

8 · Hallazgos que chocan con "backend inmutable"

Un gateway no puede resolver los marcados en rojo; requieren tocar el código sin cambiar el contrato.

Crítico
  • Firma de integridad Wompi con HMAC (debe ser SHA256 simple)
  • Webhook Wompi omite timestamp → pagos no se confirman
  • Webhook acepta todo si WOMPI_EVENTS_SECRET está vacío
  • Sin auto-confirm de 24 h fuera de mock
  • Paquetes de publicidad y Plan Pro se activan sin cobrar
  • Seed con password123 corre también en producción
Alto / medio
  • Atribución del comisionista perdida en compra guest
  • Anti-fraude (misma cédula) solo en el flujo mock
  • Dinero sin transacciones de BD (retiros, escrow); webhook no idempotente
  • Ruta Stripe en USD que se salta el escrow
  • JWT_SECRET con valor por defecto
  • Rol courier inexistente; KYC a medias

Un gateway sí mitiga: bloquear /mock y /admin públicos, rate limit, CORS, límites de tamaño, TLS.
